PR #662 is a bundle of six fixes that all share one theme: the platform was reporting success on work it never actually did. The headline one is grounding. A team member could claim an answer without ever calling a tool, and the run still settled as SUCCEEDED and billed real tokens. Now every claim must cite the tool call it came from, or the member fails. Related: compiled members were being dispatched with no tools at all, so nine-member runs finished green with zero tool calls. The rest are fail-closed corrections. An empty ontology allow-list used to let everything through instead of nothing. SQL imports skipped ontology checks entirely. The knowledge-graph service defaulted to a fake credential broker that quietly handed out the platform's own database connection instead of the user's. Status: open, waiting on code review. One open question the author deliberately left for the CTO rather than deciding alone. The strict grading rule fails members that did the real work but didn't cite it properly, and the real-model test suite is not fully green because of it. That's a product call about how hard an uncited claim should bite.

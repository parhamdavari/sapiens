Glad that unblocked you! While I was in there I noticed a few other things worth cleaning up. Roughly in order of how much they'd hurt you:

**1. The same timezone bug exists in two other test files.**
They make the identical assumption about the local TZ, so they'll fail the same way as soon as they run on a machine (or CI runner) in a different zone. Same fix applies.

**2. There's no fixed clock anywhere in the suite.**
The bug we just fixed is really a symptom of this. Any date-dependent test is fragile until there's a single frozen "now" that tests can rely on — something like `freezegun`, or a `time_source` fixture that everything date-related pulls from. That turns a whole class of flaky failures into a non-issue instead of us patching them one at a time.

**3. `conftest.py` builds the database URL by string concatenation.**
It'll break the moment a password contains an `@` (or `/`, `#`, `?`), because the URL parser will read it as the host separator. This is the kind of thing that works fine locally and then fails in staging with a confusing connection error. Worth switching to proper URL encoding of the credential parts.

**4. The suite takes ~4 minutes, and ~3 of those are one fixture.**
There's a fixture rebuilding the schema for every test class. Scoping it to the session and rolling back a transaction per test instead would likely get the whole run under a minute. Biggest speed win available by a wide margin, though it's also the most invasive change.

My suggestion: #1 and #3 are quick and low-risk, so I'd do those now. #2 is the one that actually prevents this bug from recurring. #4 is the biggest payoff but I'd want to do it as its own change so it's easy to revert if a test turns out to depend on the fresh schema.
